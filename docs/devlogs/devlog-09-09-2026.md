### Project structure:

Coming from Java, I tried mapping my project understanding
in Java over to C++. From what I understand:

`Cmake` is a meta-build system that is loosely analogous to
maven `pom.xml` files. It aids cross-platform development
and build files. It consists of:

- `CmakeList.txt` – These are the configuration files that
  tell Cmake how to configure and structure C++ projects.
  Similar to a `pom.xml` every subproject has a
  `CMakeLists.txt`.
- `CPM` or `CPM.make` – A dependency manager for (external)
  dependencies. This is still in the `CMakeLists.txt`
- `Ninja` - is a build executor to run the compilations for
  the final executable. This is generated by CMake or
  another build toolchain. Clion on Windows is using this by
  default.

Not all `CMakeLists.txt` files are the same. Some are used
to define:

- libraries – building reusable code that other targets will
  link against. There are multiple types:
    - static - great for resuing code.
    - shared - great for dynamic linking
    - interface - no source files, can carry compile
      options, include directories and/or link requirements.
      Because there is no implementation. One will may need
      to be provided.
    - object – compiles source files into object files but
      not archived into a normal library.
    - alias - doesn't build anything by itself, useful
      because it makes usage clear.
- executables – when building a runnable program.
- interfaces -

Other things covered:

- `Clang-format` is used to format the code.
- `Clang-tidy` is used to check the code.
- `RelWithDebInfo` is used to debug the code but is
  optimized. Better for measuring performance and profiling.
